# subscribe-manager 제품 요구사항 문서

작성일: 2026-11-02

문서 상태: MVP 제작 주문서

기준 문서: `docs/mvp.md`

## 1. 제품 한눈에 보기

`subscribe-manager`는 구독 결제와 생활 속 기한을 한곳에서 관리하는 웹 서비스다.

사용자는 넷플릭스 같은 구독뿐 아니라 기프티콘, 쿠폰, 포인트, 상품권, 제품 보증기간과 보장 서비스 종료일도 등록할 수 있다. 홈과 캘린더에서는 이 항목들을 날짜순으로 함께 확인한다.

이 서비스는 실제 결제, 환불 또는 구독 해지를 대신 실행하지 않는다. 사용자가 입력하거나 확인한 정보를 바탕으로 앞으로의 일정과 예상 비용을 정리하고, 공식 해지 안내와 최신 소식을 제공한다.

### 기술 조건

| 기술 | 역할 |
| --- | --- |
| React | 사용자가 보는 웹 화면 |
| FastAPI | 데이터 처리, 권한 확인, 일정·알림 작업, OpenAI와 외부 API 연결 |
| Supabase | 로그인, 데이터베이스, 비공개 이미지 보관 |

## 2. 누가 사용하는 서비스인가

### 주요 사용자

- 여러 구독의 다음 결제일과 예상 비용을 한 번에 보고 싶은 사람
- OTT뿐 아니라 AI·디자인 도구, 게임, 음악, 독서, 강의, 쇼핑·배달 멤버십, 가전 구독과 정기 배송을 함께 쓰는 사람
- 기프티콘, 쿠폰, 포인트와 상품권의 만료일을 자주 놓치는 사람
- 제품 보증기간과 애플케어·삼성케어플러스 같은 보장 서비스 종료일을 기록하고 싶은 사람
- 구독 해지 메뉴와 공식 절차를 찾는 데 어려움을 느끼는 사람
- 자신이 이용하는 서비스의 가격·혜택·기능·콘텐츠 변경 소식만 모아 보고 싶은 사람

### 처음 제공할 기본 환경

- 기본 국가: 대한민국
- 기본 통화: 원화
- 기본 시간대: `Asia/Seoul`
- 사용자는 통화와 시간대를 변경할 수 있다.

구독 금액은 실제 결제 통화와 함께 저장한다. 서비스 이름만으로 통화를 정하지 않는다. MVP는 자동 환율 변환을 필수로 제공하지 않으며, 리포트와 비용 기준 구 시각화는 원화·달러처럼 통화별로 나누어 보여준다.

## 3. 해결하려는 불편

| 사용자의 불편 | 서비스가 제공할 해결 방법 |
| --- | --- |
| 구독과 쿠폰·보증 기한이 여러 앱과 화면에 흩어져 있다. | 서로 다른 항목을 한곳에 등록하고 홈·목록·캘린더에서 함께 보여준다. |
| 다음 결제일이나 만료일을 잊는다. | D-day, 앱 안 알림, Web Push와 선택적인 Google Calendar 연동을 제공한다. |
| 스크린샷에 있는 요금제와 날짜를 다시 입력하기 번거롭다. | 이미지에서 보이는 정보를 초안으로 만들고 사용자가 확인한 뒤 저장한다. |
| 현재 구독 규모와 앞으로의 비용을 이해하기 어렵다. | 예상 청구액, 월 환산액과 근거가 있는 추정 누적액을 표·그래프·구 시각화로 보여준다. |
| 결합 멤버십의 비용이 중복 계산될 수 있다. | 직접 결제, 포함 혜택, 추가 요금과 금액 미확인 관계를 구분한다. |
| 공식 해지 경로를 찾기 어렵다. | 실제 가입·결제 경로에 맞는 공식 안내와 확인된 링크를 보여준다. |
| 내가 쓰는 서비스의 중요한 변경만 골라 보기 어렵다. | 서비스별 소식을 공통 수집하고 사용자의 구독·요금제·국가·관심사에 맞춰 보여준다. |

## 4. MVP에서 사용자가 할 수 있는 일

### 4.1 로그인과 개인정보 보호

사용자는 이메일과 비밀번호로 가입하고 로그인한다. 이메일 확인과 비밀번호 재설정은 Supabase Auth를 이용한다. 소셜 로그인은 MVP 필수 범위가 아니며, Google Calendar 연결을 위한 Google 인증은 서비스 로그인과 별개다.

이메일·비밀번호의 최대·최소 길이와 비밀번호 문자 조합은 아직 확정하지 않는다. 실제 Supabase 설정과 함께 사용자 정책으로 결정한다.

- 다른 사용자의 구독, 기한, 관심사와 이미지는 볼 수 없어야 한다.
- 이미지는 공개 주소가 아닌 비공개 공간에 보관한다.
- 이미지 보기에는 인증 또는 일정 시간이 지나면 만료되는 주소를 사용한다.
- 관리자용 비밀 키는 브라우저에 노출하지 않는다.

탈퇴를 확인하면 즉시 로그아웃하고 계정 접근, 알림과 사용자별 정기 수집 대상에서 제외한다. 원본 이미지, 관리 이력, 추출 초안과 개인 관심 정보는 요청 후 24시간 이내 삭제를 목표로 한다. 삭제 실패는 기록하고 재시도한다. 공통 소식과 공식 해지 안내는 특정 사용자의 소유가 아니므로 유지할 수 있다. 외부 제공자의 보관 정책과 백업 삭제 범위는 서비스 DB 삭제와 구분해 안내한다.

### 4.2 구독과 생활 기한 직접 등록

등록 방식은 입력 폼과 이미지 업로드 두 가지다. 문장이나 대화로 등록하는 기능은 제공하지 않는다.

사용자는 다음 항목을 직접 등록·조회·수정·삭제할 수 있다.

- 반복 결제 구독
- 기간제 구독과 멤버십
- 기프티콘, 쿠폰과 상품권
- 포인트
- 제품 보증과 보장 서비스
- 사용자가 직접 정의한 그 밖의 기한

관리 유형에 따라 필요한 입력란을 다르게 보여준다. 모르는 값은 비워 두거나 `확인 필요`로 저장할 수 있다.

금액을 입력할 때 결제 통화를 함께 고른다. 같은 서비스도 사용자와 결제 경로에 따라 청구 통화가 다를 수 있다.

사용자가 확인한 0원은 유효한 금액으로 저장하고, 금액을 모르는 상태와 구분한다. 금액 미확인은 합계에서 제외한다. 유형별 필수값, 텍스트 길이, 금액 범위와 날짜 허용 범위는 `docs/spec.md`에 `확인 필요`로 남긴다.

#### 관리 항목 삭제

관리 항목 삭제와 첨부 이미지 삭제를 분리한다. 삭제 확인창에는 과거 이력, 미래 예상 회차·내부 일정·미발송 알림, 첨부 이미지, Google 일정과 결합 구독 연결에 미치는 영향을 보여준다.

내부 삭제가 성공하면 미래 회차·내부 일정·미발송 알림을 중단하고 연결된 Google 일정 삭제를 요청한다. 이미지 또는 Google 일정 정리가 실패해도 성공한 내부 삭제를 실패로 되돌리지 않는다. `항목 삭제 완료 · 이미지 정리 실패`, `항목 삭제 완료 · Google 일정 정리 실패`처럼 부분 결과와 재시도 상태를 표시한다.

이미지를 휴지통으로 보내는 경우 기존 30일 정책을 유지한다. 관리 항목의 과거 이력 보존, 이미지 기본 처리, 항목 복구 기간과 결합 관계가 있는 항목의 삭제 방식은 확인 필요다.

### 4.3 이미지에서 등록 초안 만들기

사용자는 다음 이미지를 올릴 수 있다.

- 계정·멤버십 정보 화면
- 구독 관리·요금제 화면
- 결제일·갱신일 안내 화면
- 결제 내역·영수증·안내 메시지
- 기프티콘·쿠폰·상품권
- 멤버십·보증기간 안내

등록 순서는 다음과 같다.

1. 업로드할 이미지를 미리 본다.
2. 필요한 부분만 자르거나 이메일·전화번호 등을 직접 가린다.
3. 외부 AI로 전송될 이미지와 원본 보관 여부를 확인한다.
4. OpenAI 이미지 이해 기능이 화면에 보이는 정보로 초안을 만든다.
5. 원본 또는 분석용 이미지와 입력 폼 초안을 나란히 비교한다.
6. 누락된 값을 입력하고 잘못된 값을 수정한다.
7. 사용자가 확인한 뒤 저장한다.

서비스는 이미지에 없는 금액·날짜·결제 주기를 추측해 저장하지 않는다. `2025년 1월`처럼 연도와 월만 보이면 특정 날짜로 바꾸지 않는다.

이미지에 통화 기호나 통화 코드가 명확하면 초안에 넣는다. 통화가 불명확하면 임의로 정하지 않고 사용자에게 확인을 요청한다.

이메일·전화번호·주소·계정 ID는 별도 관리 필드나 추출 결과로 저장하지 않는다. 다만 원본이나 분석용 이미지에는 해당 정보가 남을 수 있으며, 사용자가 가리지 않은 이미지 전체를 분석하면 OpenAI로 전송될 수 있음을 전송 전에 알린다.

### 4.4 이미지 보관과 삭제

- 지원 파일은 JPEG, PNG, WebP이며 파일당 최대 크기는 10MB다. 확장자만 믿지 않고 실제 이미지 형식과 크기를 검사한다.
- 사용자별 저장 한도는 원본·분석용·임시·휴지통 파일을 모두 합쳐 100MB다.
- 한도를 넘으면 기존 파일을 자동 삭제하지 않고 사용자가 휴지통과 보관 이미지를 정리하도록 안내한다.
- 구독 계정·결제 화면은 확정 후 원본 삭제를 기본으로 제안한다.
- 기프티콘·상품권·보증 증빙은 원본 보관을 기본으로 제안한다.
- 사용자는 기본 선택을 바꿀 수 있다.
- 등록 취소 파일은 즉시 삭제 대상으로 처리한다.
- 분석 실패 또는 저장하지 않은 이미지와 초안은 마지막 활동 후 24시간 보관한 뒤 정기 작업에서 삭제한다.
- 저장이 끝나면 확정 정보와 사용자가 보관하기로 한 원본만 남기고, 불필요한 분석용 사본과 모델 원문 응답은 삭제 대상으로 처리한다.

기프티콘·쿠폰·상품권에서 `사용 완료`를 누르면 사용 완료 상태를 기록하고 이미지를 휴지통으로 보낸다.

사용 상태와 이미지 상태는 별개다. 이미지를 복원해도 사용 완료가 자동으로 취소되지 않는다.

휴지통 이동 후 30일이 지나면 삭제 대상이 되며, 실제 삭제는 이후 정기 작업에서 처리한다. 사용자는 그전에 복원하거나 즉시 삭제할 수 있다.

복원과 삭제가 동시에 요청되면 하나만 성공해야 한다. 파일 삭제에 실패하면 재시도하고 `삭제 실패` 상태를 남긴다.

### 4.5 홈·목록·필터·D-day

사용자는 홈에서 다음 정보를 확인할 수 있다.

- 오늘, 이번 주와 이번 달의 결제·갱신·만료 일정
- 해지 마감일과 사용자가 정한 검토일
- D-day
- 예상 지출 요약
- 정보가 부족해 확인이 필요한 항목
- 자신에게 관련 있는 최신 소식

전체 목록에서는 유형, 카테고리, 상태, 날짜와 정보 지원 범위로 필터링하고 이름·날짜·금액으로 정렬할 수 있다.

### 4.6 날짜와 구독 상태 관리

최초 가입일만으로 다음 결제일을 확정하지 않는다. 가입일과 결제 주기로 날짜를 계산할 수 있어도 `예상 날짜`로 제안하고 사용자 확인 전에는 확정값으로 다루지 않는다.

날짜가 없어도 항목은 등록할 수 있다. 해당 날짜가 필요한 D-day·알림·예상 지출에는 계산할 수 없는 이유를 보여준다.

월말 반복은 원래 기준일을 보존한다. 예를 들어 1월 31일 다음은 2월 말일이고, 그다음은 다시 3월 31일이다. 윤년, 사용자 시간대, 날짜만 있는 기한과 시각까지 있는 기한도 구분한다.

구독은 다음 세 상태를 따로 관리한다.

| 상태 축 | 예시 |
| --- | --- |
| 실제 이용 상태 | 체험 중, 이용 중, 일시 중지, 결제 문제 확인, 이용 종료, 확인 필요 |
| 자동 갱신 상태 | 켜짐, 꺼짐, 수동 갱신, 확인 필요 |
| 사용자 계획 | 유지 예정, 해지 검토, 특정 날짜까지 해지 예정, 재가입 검토 |

금융 연동이 없는 MVP에서는 결제 실패를 자동으로 알아냈다고 가정하지 않는다. 사용자가 입력하거나 결제 안내 이미지에서 확인한 경우에만 기록한다.

### 4.7 내부 캘린더와 알림

사용자는 내부 캘린더에서 결제·갱신·해지 마감·검토·만료·보장 종료 일정을 월간·주간·목록으로 볼 수 있다.

알림 채널은 다음과 같다.

- 앱 안 알림
- Web Push
- Google Calendar 자체 알림

기본 알림 시점은 3일 전과 당일이며, 기본 발송 시각은 사용자 시간대 기준 오전 9시다. 사용자는 항목별 또는 전체 기본값을 변경할 수 있다.

조용한 시간은 오후 10시부터 다음 날 오전 8시까지다. 이 시간의 외부 알림은 종료 후로 미루되, 발송할 때 이미 의미가 없어진 알림은 보내지 않는다. 앱 안 알림 기록은 유지한다.

알림 작업은 같은 요청이 반복 실행되지 않도록 고유 키와 로그를 사용한다. 외부 Push 요청 후 응답이 끊기면 실제 기기 도착 여부를 알 수 없으므로 `결과 불명` 상태와 제한된 재시도 정책을 사용한다. 외부 기기에 반드시 정확히 한 번 도착한다고 약속하지 않는다.

날짜 수정, 기간 연장, 이용 종료와 자동 갱신 변경 시 미래 일정과 아직 보내지 않은 알림을 새 값으로 갱신한다.

### 4.8 Google Calendar 연동

사용자는 원하는 경우 내부 일정을 Google Calendar로 보낼 수 있다.

- subscribe-manager를 원본으로 하는 단방향 연동이다.
- 사용자가 동의하면 `subscribe-manager` 전용 보조 캘린더를 만든다.
- 재연결할 때 기존 전용 캘린더를 찾아 사용하며 같은 캘린더를 중복 생성하지 않는다.
- 내보낼 일정 종류를 사용자가 선택한다.
- 날짜 변경·삭제 시 연결된 Google 일정만 갱신한다.
- 재시도해도 같은 일정이 중복 생성되지 않도록 내부 ID와 Google 이벤트 ID를 연결한다.
- 연결 해제 시 Google 일정 삭제 또는 유지 중 하나를 선택한다.
- 인증 만료나 권한 취소가 발생해도 내부 일정과 알림은 유지한다.
- 일반적인 액세스 토큰 만료는 가능한 경우 자동 갱신하고, 갱신 실패나 권한 철회처럼 사용자 조치가 필요할 때만 재연결을 요청한다.

Google에서 직접 수정한 내용을 다시 가져오는 양방향 동기화는 MVP 범위가 아니다.

앱이 만든 캘린더를 관리하는 데 필요한 최소 권한과 공개 전 OAuth 검증 필요 여부는 개발 중 공식 문서와 테스트 계정으로 확인한다. 외부 심사 완료일은 제품 일정으로 미리 확정하지 않는다.

### 4.9 예상 지출 리포트

MVP는 실제 금융 거래를 확인한 것처럼 표시하지 않는다. 등록된 요금·결제 주기·날짜와 확인 가능한 과거 요금 정보를 이용한다.

| 지표 | 의미 |
| --- | --- |
| 예상 청구액 | 미래 예상 결제 일정의 등록 요금 합계 |
| 월 환산액 | 현재 반복 요금을 한 달 기준으로 바꾼 비교값 |
| 추정 누적액 | 확인 가능한 이용 기간과 당시 요금 정보로 계산한 참고값 |

현재 요금을 과거 전체에 적용해 실제 지출처럼 보여주지 않는다. 추정 근거가 부족하면 계산하지 않거나 사용한 가정을 표시한다.

금액 미확인 항목은 무료나 0원으로 처리하지 않고 합계에서 제외한다.

> 확인된 월 환산액 35,000원 · 금액 미확인 구독 2개 제외

모든 항목의 금액이 미확인이면 `0원` 대신 `계산할 정보 없음`을 표시한다.

예정일이 지났다는 이유로 결제 완료나 실제 지출로 바꾸지 않고 `지난 회차·결제 여부 미확인`으로 표시한다.

금액은 통화별로 따로 합산한다. 원화와 달러처럼 서로 다른 통화를 그대로 더하지 않는다. 자동 원화 환산을 하지 않은 외화 항목이 있으면 리포트에 그 사실을 표시한다.

예상 결제 일정은 오늘부터 미래 12개월까지 만든다. 시간이 지나면 항상 12개월 범위를 유지하도록 부족한 기간만 보충한다. 요금·주기·날짜·자동 갱신 상태가 바뀌면 과거 기록은 유지하고 미래 일정만 갱신한다. 연간 구독도 12개월 범위 안의 다음 일정이 표시되어야 한다.

리포트는 다음 값을 구분한다.

- 선택 기간 전체 예정 청구액: 사용자 시간대 기준 시작일과 종료일을 모두 포함한 등록 일정 합계
- 선택 기간 중 남은 예정 청구액: 선택 기간 안에서 오늘 이후 남은 일정 합계. 오늘 일정 포함 여부는 확인 필요
- 월 환산액: 현재 반복 요금을 한 달 단위로 바꾼 비교값
- 추정 누적액: 확인 가능한 이용 기간과 당시 가격 근거가 있는 범위의 참고값

기간 전체에 지난 예정일이 포함되면 `등록된 일정 기준이며 실제 결제 여부는 확인하지 않음`을 표시한다. 취소·건너뜀과 금액 미확인 회차는 합계에서 제외하고 이유와 개수를 보여준다. 0원은 금액 미확인과 구분한다. 날짜·가격·상태 수정은 미래 회차만 갱신하고 리포트는 저장된 과거 회차와 새 미래 회차를 기준으로 다시 계산한다.

### 4.10 인터랙티브 구 시각화

사용자는 구독 현황을 움직이는 구, 표와 일반 그래프로 볼 수 있다.

구 하나는 하나의 이용 서비스를 뜻한다. 사용자는 구의 크기 기준을 다음 중에서 바꿀 수 있다.

- 월 환산액
- 추정 누적액
- 구독한 개월 수

구를 선택하면 요금제, 결합 관계, 다음 결제일, 예상 비용과 가입·종료·재가입 이력을 보여준다.

금액 미확인 서비스는 무료처럼 작은 구로 표시하지 않고 별도 `금액 미확인` 그룹에 둔다. 구 시각화의 수치는 표와 그래프의 수치와 일치해야 한다.

비용 기준 구 시각화는 사용자가 선택한 한 통화 안에서만 비교한다. 다른 통화 항목은 별도 통화로 전환해 보게 한다.

시각화는 자체 구현을 기본으로 한다. 우선 제공할 동작은 구 선택, 크기 기준 전환과 상세 정보 표시다. 과도한 물리 효과는 필수가 아니다. OriginKit Rubber Spheres는 화면 동작의 참고 자료로만 사용하며 라이선스와 접근 조건을 확인하기 전에는 필수 의존성으로 삼지 않는다. 모바일 성능, 동작 줄이기와 표 대체 보기를 제공한다.

### 4.11 결합 구독

사용자는 서비스 이용 관계를 다음처럼 등록할 수 있다.

- 직접 결제
- 다른 구독에 포함된 혜택
- 다른 구독을 통해 청구되는 추가 요금
- 관계는 확인했지만 금액은 확인하지 못한 연결

예를 들어 네이버 멤버십을 통해 넷플릭스를 이용한다면 상위 구독과 이용 서비스를 연결한다. 금액이 확인되지 않았다면 무료 또는 특정 할인 금액으로 확정하지 않는다.

같은 등록 요금과 예상 청구액은 하나의 비용 항목에서만 합산해 중복을 막는다.

### 4.12 공식 해지 방법 안내

사용자는 서비스 상세에서 실제 가입·결제 경로에 맞는 해지 안내를 볼 수 있다.

- 공식 웹사이트, Apple App Store, Google Play, 통신사·제휴 경로를 구분한다.
- 공식 메뉴 경로와 실제로 확인한 링크만 보여준다.
- 해지 조건과 해지 후 이용 가능 기간을 출처에서 확인할 수 있을 때만 표시한다.
- 출처, 마지막 확인일과 확인하지 못한 내용을 함께 보여준다.
- LLM이 해지 URL이나 절차를 추측해 만들지 않게 한다.

직접 해지 링크를 확인하지 못하면 공식 도움말과 메뉴 이동 경로를 제공한다. 실제 해지는 사용자가 외부 서비스에서 수행한다.

해지 안내의 근거는 서비스 공식 홈페이지·도움말·약관과 실제 결제 경로의 공식 안내로 제한한다. Apple·Google·통신사 결제는 해당 결제 경로의 공식 자료를 사용한다. 블로그와 커뮤니티는 확정 절차의 근거로 사용하지 않는다.

가격·혜택·해지 안내는 기본 7일마다 다시 확인하고, 종료일이나 적용일이 임박하면 하루 1회 확인한다. `임박`으로 판단할 남은 기간은 확인 필요다. 최초 안내와 중요한 절차 변경은 운영자 검수 전 `검수 대기`로 둔다. 초기 안내는 운영자(초기에는 프로젝트 소유자)가 공식 원문과 링크를 검토한 뒤 공개한다.

### 4.13 서비스별 최신 소식

MVP의 최신 소식 대상은 다음과 같다.

- OTT의 공개 예정작·신규 작품·제공 종료 소식
- AI 서비스의 모델·기능·한도·요금제 변경
- 디자인 도구의 편집·협업·생성형 AI 기능 변경
- 게임 구독의 추가·제공 종료 게임과 혜택 변경
- 쇼핑·배달 멤버십의 가격·적립·배송·쿠폰 조건 변경
- 음악·독서·강의의 콘텐츠와 이용권 변경
- 가전 구독의 상품·관리 서비스·혜택 변경

서비스별 소식은 사용자마다 다시 검색하지 않고 공통으로 수집·저장한다. 이후 사용자의 구독·요금제·국가·결제 경로·관심사에 맞춰 관련성을 판단한다.

각 소식에는 다음 정보를 표시한다.

- 출처 링크
- 발표일과 실제 적용일
- 대상 국가·요금제·가입 조건
- 마지막 확인일
- 내 구독에 미치는 영향 또는 `확인 필요`

새 모델이 발표됐다는 사실과 사용자의 요금제에서 이용 가능하다는 사실을 따로 확인한다.

`검색 실패`, `확인한 범위에서 새 소식 없음`, `소식은 있으나 적용 조건 미확인`, `원문 확인 실패`를 서로 다르게 표시한다. 검색한 일부 OTT 작품을 전체 편성 목록처럼 표현하지 않는다.

일반 소식은 서비스별로 하루 1회 확인한다. 사용자마다 검색하지 않고 공통 결과를 재사용한다. 예산 초과나 외부 오류로 갱신하지 못하면 마지막 확인일과 `재확인 필요` 상태를 보여준다. 공식 출처가 확인된 소식은 자동 게시할 수 있지만, 대상 국가·요금제·가입 조건이 불명확하면 `확인 필요`를 함께 표시한다.

### 4.14 직접 등록과 정보 지원 범위

사용자는 카탈로그에 없는 서비스도 직접 등록할 수 있다. 해지 안내와 최신 소식은 공식 자료와 검색 기준을 갖춘 지원 카탈로그의 서비스에 제공한다.

지원하지 않는 서비스는 조용히 제외하지 않고 다음 중 하나를 표시한다.

- 직접 관리만 가능
- 자료 수집 중
- 정보 확인 필요

초기 지원 후보는 다음과 같다.

- OTT: 넷플릭스, 티빙, 라프텔
- AI: ChatGPT, Gemini, Perplexity
- 디자인: Canva, Adobe
- 게임: Xbox Game Pass
- 멤버십: 쿠팡 와우, 네이버플러스 멤버십
- 독서: 밀리의 서재
- 가전: LG전자 가전 구독

이 목록은 출시 시 지원을 보장하는 목록이 아니다. 소식과 해지 안내의 지원 여부를 서비스·결제 경로별로 따로 관리한다. 공식 자료와 실제 동작을 확인한 기능만 `지원`으로 표시하고, 확인하지 못한 경우 `검증 중` 또는 `지원하지 않음`으로 표시한다. 목록 밖의 서비스도 직접 등록과 기본 관리가 가능하다.

### 4.15 OpenAI 모델과 비용 제한

이미지 추출과 소식·해지 안내 검색은 `gpt-5.4-mini`를 첫 후보로 한다. 공식 OpenAI 문서상 이 모델은 이미지 입력, 구조화 출력과 Responses API의 웹 검색을 지원한다. 다만 실제 프로젝트의 모델 접근 권한, 필요한 기능 조합, 결과 품질과 비용은 구현 전에 샘플 호출로 검증한다. 모델명과 검색 설정은 운영 설정으로 교체할 수 있게 한다.

초기 운영 제한은 다음과 같다.

- 이미지 분석: 사용자당 하루 10회
- 이미지 분석 예상 비용: 사용자당 하루 US$0.20
- 검색·모델 호출 전체: 서비스 기준 하루 US$2
- 초기 개발·시험 누적 예산: US$10

횟수와 예산 중 먼저 도달한 제한을 적용한다. 호출 전 예상 비용과 이미 진행 중인 작업을 고려해 새 호출을 막을 수 있다. 예상 비용은 실제 청구액과 다를 수 있음을 표시한다. 한도에 도달해도 직접 등록과 기존 데이터 조회는 계속 사용할 수 있다. 사용자의 새로고침은 새 검색을 바로 만들지 않는다.

참고: [GPT-5.4 mini 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision), [웹 검색 문서](https://developers.openai.com/api/docs/guides/tools-web-search)

### 4.16 운영 검수와 공개

초기 운영자는 프로젝트 소유자다. 일반 사용자는 해지 안내와 소식을 읽을 수 있지만 검수·공개·수정·비공개 작업은 할 수 없다.

해지 안내는 `초안`, `검수 대기`, `공개`, `재확인 필요`, `비공개` 상태로 관리한다. 운영자는 공식 링크를 직접 열어 서비스·국가·요금제·결제 경로와 핵심 조건을 확인한다. 중요한 변경이 발견되면 기존 안내를 최신 정보처럼 그대로 두지 않고 `재확인 필요` 또는 `비공개`로 전환한다. 어떤 방식을 기본으로 할지는 확인 필요다.

최신 소식은 공식 출처와 필수 정보가 확인되면 자동 공개할 수 있다. 적용 조건이 불명확하면 `확인 필요`를 표시한다. 운영자는 출처 범위 안에서 요약을 수정하거나 중복·오류·근거 부족 소식을 비공개 처리할 수 있다.

모든 검수·공개·수정에는 검토자, 검토 시각, 변경 전·후 내용과 이유를 남긴다. MVP 운영 도구는 큰 관리자 화면보다 운영자만 접근하는 제한된 검수 도구를 추천하지만, 별도 관리자 화면과 제한된 도구 중 어떤 방식을 사용할지는 확인 필요다. 운영 방식 확정 전에는 관리자 화면 개발을 필수 범위로 확정하지 않는다.

모바일에서는 다가오는 일정과 빠른 등록을 먼저 보여준다. 상태는 색만으로 구분하지 않고 글자를 함께 표시한다. 움직이는 구 화면에는 동작 줄이기와 키보드 조작, 표 대체 보기를 제공한다.

## 6. MVP 완료 기준

다음 조건을 모두 만족하면 첫 버전이 완성된 것으로 본다.

### 계정과 접근

- 이메일·비밀번호 가입, 이메일 확인, 로그인과 비밀번호 재설정이 작동한다.
- 로그인한 사용자가 본인의 데이터와 이미지만 볼 수 있다.
- 다른 사용자의 주소나 ID를 알아도 데이터에 접근할 수 없다.
- 탈퇴 확인 즉시 접근과 알림이 중단되고 사용자 소유 자료가 24시간 이내 삭제 대상으로 처리된다.

### 등록과 이미지

- 구독, 기프티콘, 상품권, 포인트, 보증과 기타 기한을 유형별 폼으로 등록·조회·수정·삭제할 수 있다.
- 이미지에 보이는 정보만 초안으로 만들고 사용자가 확인해야 저장된다.
- 연·월 날짜가 임의의 날짜로 변하지 않는다.
- 이미지 외부 전송 범위와 원본 보관 여부를 사용자가 확인할 수 있다.
- JPEG·PNG·WebP만 허용되고 파일당 10MB, 사용자당 100MB 제한이 적용된다.
- 한도 초과 시 기존 파일이 자동 삭제되지 않는다.
- 임시 파일, 휴지통, 복원, 즉시 삭제와 삭제 실패 상태가 정의대로 작동한다.
- 미저장 이미지와 초안이 마지막 활동 후 24시간이 지나면 삭제 대상으로 처리된다.

### 일정과 상태

- 가입일만으로 다음 결제일을 확정하지 않는다.
- 날짜가 없는 항목도 저장되고 제한된 기능의 이유가 표시된다.
- 월말·윤년·시간대 계산이 정의된 규칙과 일치한다.
- 실제 이용 상태, 자동 갱신 상태와 사용자 계획을 따로 변경할 수 있다.

### 캘린더와 알림

- 내부 캘린더에서 모든 일정 유형을 필터링할 수 있다.
- 앱 안 알림과 Web Push를 설정할 수 있다.
- 기본 3일 전·당일 오전 9시 알림과 오후 10시~오전 8시 조용한 시간이 사용자 시간대로 적용된다.
- 정기 작업이 다시 실행돼도 같은 발송 작업을 중복 생성하지 않는다.
- 외부 전달 실패와 결과 불명 상태가 기록되고 제한된 횟수로 재시도된다.
- Google Calendar 연결 실패나 만료가 내부 일정에 영향을 주지 않는다.
- 재연결해도 전용 보조 캘린더가 중복 생성되지 않는다.

### 예상 지출과 시각화

- 예상 청구액, 월 환산액과 추정 누적액이 서로 구분된다.
- 다른 통화를 더하지 않고 통화별 합계와 외화 미환산 안내가 표시된다.
- 미래 예상 일정이 12개월 범위로 유지되고 연간 구독의 다음 일정도 범위 안에서 표시된다.
- 계산 근거와 제외된 금액 미확인 항목이 표시된다.
- 계산할 금액이 하나도 없을 때 `계산할 정보 없음`을 표시한다.
- 결합 구독의 비용이 중복 합산되지 않는다.
- 구 시각화, 표와 일반 그래프의 수치가 일치한다.

### 해지 안내와 최신 소식

- 해지 절차와 URL에는 실제로 확인한 공식 출처와 확인일이 있다.
- 결제 경로가 다른 안내를 섞지 않는다.
- 서비스별 소식이 공통 저장되고 사용자별로 재사용된다.
- 발표일·적용일·국가·요금제·확인일과 미확인 사항을 구분한다.
- 검색 실패, 새 소식 없음과 적용 조건 미확인이 다르게 보인다.
- 일부 OTT 검색 결과를 전체 편성 목록이라고 표현하지 않는다.
- 정해진 갱신 주기, 공통 결과 재사용과 검수 대기 상태가 적용된다.
- AI 한도에 도달해도 직접 등록과 기존 데이터 조회가 작동한다.

## 8. 외부 검증과 아직 확인할 사항

다음 항목은 제품 정책이 아니라 외부 서비스의 실제 조건이다. 구현 전에 공식 문서, 프로젝트 콘솔과 샘플 동작으로 확인하고, 확인 전에는 지원 완료로 표시하지 않는다.

| 검증 항목 | 현재 결정 | 확인할 내용 |
| --- | --- | --- |
| Supabase Auth | 이메일·비밀번호, 이메일 확인, 비밀번호 재설정 사용 | 메일 발송 설정·제한, 리디렉션 주소와 운영 도메인 |
| Supabase Storage | 파일당 10MB, 사용자당 100MB 제품 제한 | 프로젝트 전체 용량·전송량·요금과 파일 삭제 실패 처리 |
| 계정 탈퇴 | 사용자 자료 24시간 이내 삭제 목표 | Supabase Auth 사용자 삭제, 외부 제공자 보관과 백업 삭제 범위 |
| Web Push | 앱 안 알림과 함께 MVP 제공 | 브라우저·운영체제별 권한, PWA 설치 조건과 실제 전달 동작 |
| OpenAI | `gpt-5.4-mini` 첫 후보, 설정으로 교체 가능 | 프로젝트 접근 권한, 이미지+구조화 출력과 웹 검색 조합, 품질·비용 샘플 |
| Google Calendar | 전용 보조 캘린더 단방향 연동 | 최소 OAuth 권한, 토큰 갱신, 공개 전 검증 필요 여부와 심사 일정 |
| 해지·소식 카탈로그 | 분야별 초기 후보 확정 | 서비스·결제 경로별 공식 자료 접근 가능 여부와 실제 갱신 결과 |
| OriginKit | 자체 구현이 기본, 참고만 함 | 참고 범위가 라이선스와 접근 조건에 맞는지 여부 |

후속 OTT 추천의 데이터 제공자는 아직 정하지 않는다. 후속 검토 때 TMDB의 국내 제공처 정보, 각 OTT의 공식 발표와 계약형 데이터 제공자의 지원 범위를 비교한다. 현재 제공 여부와 공개 예정일은 별도 정보로 다루며, 무료로 모든 OTT의 전체 편성 정보를 얻을 수 있다고 가정하지 않는다. MVP의 OTT 소식은 웹 검색과 공식 출처를 이용한다.

### 추가 정책 확인 필요

- 회원가입 비밀번호와 주요 입력값의 길이·범위·필수 여부
- 관리 항목 삭제 시 과거 이력·첨부 이미지·결합 관계 처리와 항목 복구 기간
- 오늘 예정 회차를 남은 예정 청구액에 포함할지 여부
- 제한된 운영 도구와 별도 관리자 화면 중 운영 방식
- 추가 운영자 지정·권한과 중요 변경 안내의 공개 방식
- 종료일·적용일이 `임박`했다고 판단할 남은 기간
- Web Push 결과 불명과 외부 API 실패의 최대 재시도 횟수·간격
- 파일·계정 자료 삭제가 계속 실패할 때 재시도 종료 또는 운영자 확인으로 전환할 기준
