# subscribe-manager 서비스 정의서

작성일: 2026-11-06
상태: MVP 구현 기준

## 1. 서비스 한 줄 정의

`subscribe-manager`는 반복 결제 구독과 생활 속 기한을 한곳에 기록하고, 사용자가 확인한 정보와 앞으로의 일정·예상 비용·관련 소식을 구분해 보여주는 개인용 웹 서비스다.

서비스는 결제·환불·해지를 대신 실행하지 않는다. 사용자가 입력하거나 확인한 정보를 기준으로 일정과 비용을 정리하고, 필요한 행동을 놓치지 않도록 돕는다.

## 2. 대상 사용자와 핵심 문제

### 대상 사용자

- 여러 구독의 다음 결제일과 예상 비용을 한 번에 보고 싶은 사람
- OTT 외에 AI·디자인·생산성·게임·음악·쇼핑·배달 멤버십을 함께 쓰는 사람
- 기프티콘·쿠폰·상품권·포인트의 만료일을 자주 놓치는 사람
- 제품 보증과 보장 서비스의 종료일을 기록하고 싶은 사람
- 공식 해지 경로와 서비스 변경 소식을 빠르게 확인하고 싶은 사람

### 해결하는 문제

| 문제 | 서비스의 해결 방법 |
| --- | --- |
| 정보가 여러 앱과 화면에 흩어짐 | 구독과 생활 기한을 같은 목록·홈·캘린더에서 관리 |
| 다음 결제일·만료일을 잊음 | D-day, 앱 알림, Web Push, 선택적 Google Calendar 내보내기 |
| 이미지 내용을 다시 입력하기 번거로움 | 이미지에서 등록 후보를 만들고 사용자가 검토·확정 |
| 앞으로의 비용을 이해하기 어려움 | 통화별 예상 청구액·월 환산액·기간 리포트 제공 |
| 공식 해지 경로를 찾기 어려움 | 결제 경로별 공식 안내와 출처·확인일 제공 |
| 중요한 서비스 변경을 놓침 | 공통 소식 수집 후 구독·요금제·국가 기준으로 관련성 표시 |

## 3. 제품 원칙

1. **확정값과 추정값을 분리한다.** 직접 입력, 이미지 추출 후보, 사용자 확인값, 검색 자료, 계산값의 출처와 상태를 구분한다.
2. **모르는 값은 추측하지 않는다.** 금액·날짜·조건이 이미지나 공식 자료에 없으면 비워 두거나 `확인 필요`로 표시한다.
3. **사용자가 최종 결정한다.** 이미지 초안, 해지 안내, 소식은 검토를 돕는 기능이며 자동 결제·자동 해지·자동 구매를 수행하지 않는다.
4. **같은 데이터를 여러 화면에서 다르게 보여준다.** 홈·목록·상세·캘린더·리포트는 동일한 관리 항목과 이벤트를 공유한다.
5. **개인 데이터와 공통 데이터를 분리한다.** 사용자별 구독·이미지·관심 정보는 다른 사용자에게 노출되지 않으며, 공통 카탈로그·소식과 분리해 관리한다.
6. **실제 사실과 예상 일정을 구분한다.** 예정 결제일은 결제 완료를 뜻하지 않고, 해지 안내를 열었다고 해지가 완료된 것으로 처리하지 않는다.

## 4. 관리 대상

### 구독·결제 항목

- 반복 결제 구독
- 기간제 구독·멤버십
- 기타 결제 기한

### 생활 기한 항목

- 기프티콘·쿠폰·상품권
- 포인트
- 제품 보증·보장 서비스
- 사용자가 직접 정의한 기타 기한

서비스 카탈로그에 없는 항목도 사용자가 직접 이름을 입력해 등록할 수 있다. 유료 멤버십과 만료 이벤트는 하나의 관리 항목 아래 연결하며, 사용자가 별도 목적의 항목을 만들 때만 중복 가능성을 안내한다.

## 5. 사용자 흐름

### 직접 등록

1. 관리 유형을 선택한다.
2. 유형에 맞는 서비스명·금액·통화·날짜·상태·알림·메모를 입력한다.
3. 모르는 값은 비워 두거나 `확인 필요`로 표시한다.
4. 날짜·반복·알림 미리보기를 확인한다.
5. 저장 후 홈·목록·캘린더·리포트에 반영한다.

### 이미지 등록 보조

1. 이미지의 미리보기와 외부 AI 전송 동의를 확인한다.
2. 필요한 부분을 가리거나 자른다.
3. 서버가 허용된 필드만 추출해 입력 초안을 만든다.
4. 원본과 초안을 비교해 누락·오류를 수정한다.
5. 사용자가 확정한 뒤에만 관리 항목을 저장한다.

이미지에 없는 정확한 금액·날짜·주기는 저장하지 않는다. `2025년 1월`처럼 일부 정밀도만 확인된 날짜는 연·월로 보존하고 특정 일자로 바꾸지 않는다. 이메일·전화번호·주소·계정 ID는 등록 필드로 추출·저장하지 않는다.

### 소식·해지 안내 확인

공식 HTTPS 출처와 확인일이 있는 자료만 확정 정보로 표시한다. 출처·적용 대상·결제 경로가 불명확하면 `확인 필요` 상태로 남긴다. 검색 실패, 새 소식 없음, 조건 불명확은 서로 다른 상태로 보여준다.

## 6. 주요 화면

| 화면 | 책임 |
| --- | --- |
| 홈 | 가까운 결제·만료·검토 일정, D-day, 확인 필요 항목, 관련 소식 요약 |
| 전체 목록 | 유형·카테고리·상태·날짜·지원 범위 필터와 이름·날짜·금액 정렬 |
| 등록·수정·상세 | 관리 유형별 입력, 이미지 초안 검토, 상태·날짜·가격·삭제 영향 확인 |
| 캘린더 | 결제·갱신·해지 마감·검토·만료 이벤트의 월간·주간·목록 보기 |
| 리포트 | 통화별 예상 청구액, 월 환산액, 기간별 지출과 서비스 비교 |
| 알림·설정 | 앱 알림, Web Push, 시간대·조용한 시간, Google Calendar 연결 |
| 소식 | 사용자 관련 소식, 공통 OTT 편성 소식, 출처·발표일·적용일·스크랩 |
| 운영 도구 | Phase 8 수집 결과 검토, 공지사항 관리, 서비스별 수집 상태 확인 |

모든 상태는 색상만으로 구분하지 않고 텍스트를 함께 제공한다. 모바일에서는 일정·등록·주요 상태를 우선 노출한다.

## 7. 데이터와 상태 기준

- 기본 국가는 대한민국, 통화는 KRW, 시간대는 `Asia/Seoul`이며 사용자가 변경할 수 있다.
- 금액은 `amount + currency + 의미`로 저장한다. 확인된 0원과 금액 미확인을 구분하고, 통화가 다른 금액은 자동 환산하지 않는다.
- 날짜는 연·월·날짜·날짜/시각의 확인 정밀도를 보존한다.
- 반복 결제의 월말·윤년 계산은 원래 기준일을 보존하는 예상 규칙이며 실제 결제 증거가 아니다.
- 실제 이용 상태, 자동 갱신 상태, 사용자 계획은 서로 다른 상태 축으로 관리한다.
- 금액·날짜가 없는 항목도 등록할 수 있지만, 계산할 수 없는 이유를 화면에 표시한다.
- 이미지 보관 상태와 쿠폰 사용 상태는 독립적으로 관리한다. 사용 완료 이미지는 휴지통으로 이동하며 기본 30일 복원 기간을 둔다.

## 8. 알림·외부 연동

- 앱 내 알림은 외부 푸시 실패와 관계없이 기록한다.
- Web Push는 사용자의 권한·기기 구독·HTTPS 조건이 필요하며 정확한 도착을 보장하지 않는다.
- Google Calendar는 앱을 원본으로 하는 단방향 내보내기다. 앱 이벤트와 Google 이벤트 ID를 매핑해 중복 생성을 막는다.
- 외부 연동 실패나 인증 만료가 내부 일정·관리 항목을 삭제하거나 중단시키지 않는다.

## 9. 보안·개인정보

- React는 사용자 화면, FastAPI는 권한 확인·외부 API·작업 경계, Supabase는 Auth·DB·Storage를 담당한다.
- 사용자 데이터와 공통 카탈로그·소식은 분리하고 DB RLS와 서버 권한 검사를 함께 적용한다.
- 이미지는 private Storage에 저장하고 인증 또는 만료되는 서명 URL로만 제공한다.
- API 키·서버용 Supabase 키·OAuth 비밀값은 브라우저와 Git에 넣지 않고 `.env`에서 관리한다.
- 계정 탈퇴 시 즉시 접근을 중단하고 개인 데이터 정리를 요청한다. 공통 소식·공식 안내는 개인 소유 데이터와 구분해 유지할 수 있다.

## 10. 현재 구현 범위와 제외 범위

### 구현·운영 준비 범위

- 계정·설정·사용자별 관리 항목 CRUD
- 구독·생활 기한 공통 폼, 날짜 정밀도, 상태·알림·리포트
- 이미지 등록 초안과 원본·휴지통 관리
- Web Push와 Google Calendar 단방향 연동
- 공식 해지 안내와 Phase 8 서비스 소식 수집·검수
- 운영자 공지사항과 미인증 계정 정리 작업

### MVP에서 하지 않는 일

- 실제 결제·환불·해지 실행
- 은행·카드·앱스토어 자동 거래 연동
- Google Calendar 양방향 동기화
- 환율 API 기반 자동 환산
- OTT 전체 편성표를 보장하는 수집 또는 추천 결과의 확정적 보장
- 대화 문장만으로 관리 항목을 자동 저장

## 11. 기술 구성

| 구성 | 역할 |
| --- | --- |
| React + Vite + TypeScript | 웹 UI와 클라이언트 상태 |
| FastAPI | API, 권한 검사, 이미지·소식·알림·정리 작업 |
| Supabase Auth/Postgres/Storage | 인증, 관계형 데이터, 비공개 이미지 저장 |
| OpenAI API | 사용자가 동의한 이미지 초안과 제한된 공식 소식 검색 |

상세 요구사항과 사용자 행동 명세는 [`docs/PRD.md`](./PRD.md)와 [`docs/spec.md`](./spec.md), 단계별 실행 계획은 [`docs/plan.md`](./plan.md)에서 관리한다.
