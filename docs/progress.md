## 2026-11-02 · 이미지 분석 결과를 Phase 3 공통 폼에 연결

- Phase 3의 유형 선택, 유형별 입력란, 날짜 정밀도, 분류·알림·메모 영역을 `ManagedItemFormFields` 공통 컴포넌트로 분리해 직접 등록과 이미지 등록이 함께 사용하도록 변경했다.
- 검증과 저장 payload 정규화도 `validateManagedItemDraft`, `buildManagedItemPayload`로 공통화했다. 이미지 등록은 최종 저장 전까지 `items` 행을 만들지 않는다.
- Phase 4의 별도 `서비스 이름·메모` 초안 폼을 제거하고 반복 구독, 기간제 멤버십, 기프티콘, 쿠폰, 상품권, 포인트, 보증과 기타 기한의 전체 공통 폼을 표시한다.
- 서버 추출은 사용자가 선택한 관리 유형을 유지하고, `detected_fields`에 실제 감지됐다고 명시된 허용 필드만 프론트 초안에 반영한다. 미감지 금액·통화·날짜·상태는 null로 정리하며 발행일·구매일을 만료·갱신일로 쓰지 않도록 프롬프트 규칙을 강화했다.
- 이미지에서 채운 입력란에는 `이미지에서 입력됨` 표시를 붙이고 사용자가 수정하면 표시를 제거한다. 재분석이 사용자 작성값을 덮을 수 있으면 확인창을 거친다. 분석 실패 뒤에도 업로드된 이미지와 같은 전체 폼에서 직접 입력할 수 있다.
- 데스크톱은 원본 이미지와 전체 폼을 나란히, 900px 이하에서는 위아래로 배치한다. 원본 보관 선택, AI 전송 동의와 서버 분석 한도 처리는 유지했다.
- 검증 완료: 프론트 4개 파일 18개 테스트, 프로덕션 빌드, 백엔드 12개 테스트와 Ruff 검사를 통과했다. 부분 기프티콘 추출, 미감지값 제외, 연·월 정밀도, 수동 입력 보존, 사용자 수정값의 최종 payload와 서버 감지 필드 제한을 자동화 테스트로 확인했다.
- 검증하지 못함: 첨부 예시 파일이 현재 작업 환경에 전달되지 않아 해당 원본으로 실제 OpenAI 호출을 실행하지 못했다. 원격 Supabase Storage 업로드·확정과 저장 후 실제 상세 화면의 브라우저 통합 확인도 외부 세션이 필요하다.

- 이미지 분석 후에도 관리 유형을 변경할 수 있게 했다. 변경 시 `image_assets.management_type`을 함께 갱신하고 이전 유형의 서버 추출 초안과 분석 상태를 초기화해 새 유형으로 다시 분석할 수 있게 했다. 이름·카테고리·메모는 사용자 확인 후 유지한다.
- 이미지 등록의 `분석 근거` 영역을 제거했다. 필드별 `이미지에서 입력됨` 표시는 유지한다.
- `AI 분석 시작`은 이미지가 있고 AI 처리 서버 전송 동의가 체크됐으며 현재 처리 중이 아닐 때만 활성화한다. 원본 보관 선택은 활성 조건에 포함하지 않는다.
- 직접 등록의 관리 유형·식별 이름과 조건부 필수 통화·포인트 단위에 `*`를 표시했다. 금액 입력 폼의 통화 기본값은 KRW이며 이미지 등록에서는 미확인 통화를 추측하지 않도록 빈 값으로 시작한다.
- 결제 경로에 토스페이·카카오페이·네이버페이·카드사를 추가하고, 카테고리 후보를 영상·OTT부터 건강·운동·기타까지 요청된 13개 값으로 교체했다.
- 전체 목록 상태 배지가 실제 구독 상태 또는 생활 기한 상태를 기준으로 이용·유효, 미사용, 사용 완료·종료·만료, 일시 중지·확인 필요, 결제 확인을 서로 다른 색으로 표시하도록 변경했다.
- 자동화 검증에 직접 등록 기본 통화, 필수 표시, 새 결제 경로·카테고리, 분석 버튼 AND 조건과 목록 상태 키 검증을 추가했다.
- 다음 할 일: 인증된 원격 세션에서 분석 완료 → 유형 변경 → 새 유형 재분석 → 저장 흐름과 목록 상태 배지의 실제 브라우저 표시를 확인한다.

## 2026-11-02 · 이미지 분석 후 유형 변경 시 값 유지

- 이전 구현은 다른 유형의 숨은 전용 필드가 저장되는 것을 막기 위해 유형 변경 시 초안을 초기화했지만, 공통 대응 필드까지 함께 지우는 문제가 있었다.
- 유형 변경 시 이름, 금액·통화, 시작·기한 날짜와 정밀도, 카테고리, 메모 등 새 유형에도 같은 입력란이 있는 분석값과 사용자 수정값을 유지하도록 변경했다.
- 요금제, 사용처, 포인트 단위, 결제 주기·경로, 조건과 상태처럼 새 유형에서 실제로 표시하는 필드만 선택적으로 이어받고, 새 유형에 없는 필드는 저장 payload에 남기지 않는다.
- 이미지 자산의 `management_type`과 보관된 추출 초안의 유형도 함께 변경하며 분석 완료 상태는 유지한다. 변경한 유형으로 재분석하면 새 유형 기준 결과로 교체할 수 있다.
- 자동화 테스트에 기프티콘 분석값을 반복 구독으로 변경할 때 공통 값은 유지되고 사용처·이용 조건 같은 비호환 필드는 제외되는 시나리오를 추가했다.

## 2026-11-02 · 직접 등록 카테고리와 이미지 등록 명칭 보정

- 직접 등록의 실제 통화 기본값이 `KRW · 원화`로 유지되는 것을 다시 확인했다.
- 카테고리에서 기존 `영상·콘텐츠`, `쇼핑·생활` 값을 제외하고 `영상·OTT`를 `영상·콘텐츠·OTT`로 변경했으며 `라이프·기록`을 추가했다. `기타`는 후보 목록의 마지막에 유지했다.
- 관리 목록의 `스크린샷 등록` 버튼 이름을 `이미지 등록`으로 변경했으며 이동 경로 `/images/new`는 유지했다.
- 자동화 테스트에서 변경된 카테고리의 포함·제외와 `기타`의 마지막 순서를 확인한다.

## 2026-11-02 · 이미지 등록 폼 기본값 통일

- 이미지 등록은 이미 Phase 3의 공통 `ManagedItemFormFields`를 사용하므로 필수 `*`, 토스페이·카카오페이·네이버페이·카드사 결제 경로와 최신 카테고리 후보가 직접 등록과 동일하게 표시된다.
- 이미지 등록의 실제 통화도 직접 등록과 동일하게 `KRW · 원화`로 시작하도록 변경했다. AI가 다른 통화를 명확히 추출하면 해당 값으로 바꾸고 자동 입력 표시를 붙인다.
- 부분 추출 테스트와 공통 폼 렌더링 테스트의 이미지 등록 통화 기대값을 KRW로 변경했다.

## 2026-11-02 · 기간 만료 상태 자동화와 구형 카테고리 정리

## 2026-11-02 · 이미지 영구 삭제 실패 보정

- 소유자 확인이 끝난 영구 삭제는 서버용 Supabase 권한을 우선 사용하고, 서버 키가 없는 개발 환경에서는 사용자 토큰과 Storage RLS를 사용하도록 변경했다.
- 사용자 UUID 폴더 경로를 기준으로 본인 파일만 조회·수정·삭제할 수 있도록 Storage 정책 보정 마이그레이션을 추가했다. 다른 사용자 폴더에는 접근할 수 없다.
- Storage 삭제가 실패해 `failed`가 된 이미지는 휴지통 탭에 계속 표시하고 `삭제 재시도`를 제공한다. 성공하면 휴지통·영구 삭제 예정 시각을 비우고 화면에서 제외한다.
- 다음 할 일: 새 마이그레이션을 연결된 Supabase 프로젝트에 적용한 뒤 기존 실패 항목에서 `삭제 재시도`를 실행한다.
